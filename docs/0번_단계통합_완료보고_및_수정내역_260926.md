### 2-2. 추가 기능 네 가지

**① place 전 차체 정지 확인**

차량이 완전히 멈추기 전에 짐을 내리면 위험함. 기존에는 도착 신호만 오면 로봇 팔이 즉시 동작했으므로, 카터가 미세하게 미끄러지는 중에도 place 가 시작될 수 있었음. 현재는 **차체가 0.5초 이상 실제로 정지한 것을 확인한 뒤에만** 팔이 동작함. 정지가 확인되지 않으면 팔을 움직이지 않고 `BASE_NOT_SETTLED` 로 결과를 반환함.

**② 도킹 위치 기록**

카터의 실제 정지 좌표를 한 줄 출력함. 판정은 하지 않고 기록만 수행함. 팔이 닿는 거리를 수치로 확정하기 위한 자료임. 2026-09-26 통과 시 이 출력으로 `팔 베이스 ~ place 대상 0.809 m` 를 확보함.

```
[도킹] 카터 본체 world (-2.161, -2.738), place 대상까지 x -0.026 m, y -1.169 m, 직선 1.170 m
```

**③ 운반 중 앱 종료 방지**

`standalone_app.py` 에는 운반 중 팔레트가 30 mm 이상 밀리면 오류를 내는 안전 검사가 있음. 그 오류가 프로그램 최상위까지 전달되어 **Isaac Sim 전체가 종료**되는 현상이 있었음(2026-09-24 실측에서 발생). 현재는 해당 오류를 받아 **기록 한 줄만 남기고 실행을 계속**함.

안전 검사 자체는 그대로임. 다음 place 명령 시 동일 검사가 재실행되며, 그때는 `MOTION_FAILED` 라는 **결과 메시지로 정상 보고**됨. 실패를 은폐한 것이 아니라, 앱 종료 대신 결과로 보고하도록 변경한 것임.

**④ Isaac Sim 뷰포트 시점 지정**

장면 파일에 저장된 기본 시점이 비전룸을 향하고 있어 화면 녹화 시 **카터가 보이지 않았음**. 기존에는 사람이 마우스로 시점을 변경해야 했음. 현재는 실행 시 환경변수 한 줄로 원하는 카메라 시점이 자동 적용됨. **환경변수 미지정 시 아무 동작도 하지 않으므로 기존 실행에 영향 없음.**

```bash
export SMARTFARM_VIEW_CAMERA=/World/ProcessCameras/Cam2_Nav2Place
```

### 2-3. 원복 방법

네 건 모두 추가만 수행했고 기존 줄은 변경하지 않았음. `[navigation 날짜]` 주석이 붙은 블록만 삭제하면 원본 상태로 복귀함. `git revert` 는 다른 변경분과 섞이므로 권장하지 않음.

## 5. place 이후 구간과의 연결

### 5-1. 본 구간의 종료 지점

본 구간은 `PLACE_INSPECT` 가 `SUCCEEDED` 로 종료되는 시점까지임. 그 시점의 상태는 다음과 같음.

| 항목 | 상태 |
|---|---|
| 팔레트 | 턴테이블 줄기 벨트 위에 안착 |
| 카터 | 도킹 자세 유지, 정지 상태. 포크 인출 완료 |
| 컨베이어 | place 중 정지했다가 자동 재가동되어 팔레트를 비전룸 방향으로 반송함 |
| 결과 메시지 | `/sim_task/result` 에 `PLACE_INSPECT / SUCCEEDED` |

2026-09-26 통과 시 실제 로그임.

```
[컨베이어] 줄기 벨트 정지 (로봇 놓기 중)
[컨베이어] Pallet_01 벨트 감지 — 반송 시작 (-2.186, -3.550)
[컨베이어] 줄기 벨트 재가동
[컨베이어] Pallet_01 카메라 앞 정지 (-0.496, -6.728)
```

팔레트는 이미 비전룸 카메라 앞까지 자동 이송되어 정지한 상태임. 다음 구간은 이 지점에서 시작함.

### 5-2. 인계 지점

**인계 지점 ① 컨베이어 재가동 신호**

컨베이어는 팔레트를 카메라 앞에 정지시킨 뒤 다음 둘 중 하나를 대기함.

| 설정 | 동작 | 적용 상황 |
|---|---|---|
| `auto_resume=None` | `inspection_done()` 호출까지 무한 대기 | 검사 담당이 연결된 정식 구성 |
| `auto_resume=10.0` | 10초 후 자동 배출 | 검사 없이 앞 구간만 확인하는 구성. 현재 설정임 |

`standalone_app.py` 가 `--no-vision-station` 여부에 따라 두 값을 자동 선택함. 따라서 다음 구간 연결의 실질은 **검사 종료 시 `conveyor.inspection_done()` 을 호출할 주체를 정하는 것**임.

**인계 지점 ② Task Manager 명령 순서**

인터페이스 설계서 `docs/02-interfaces.md` 에 순서가 이미 정의되어 있음.

| 순서 | operation | 수신 노드 | 성공 조건 |
|---|---|---|---|
| 1 | `PICK_HARVEST` | 시뮬 실행기 | `safe_to_navigate=true` |
| 2 | `NAVIGATION` | 주행 노드 | `reached_station=FEEDER_DOCK` |
| 3 | `PLACE_INSPECT` | 시뮬 실행기 | 놓기 검증 통과. **본 구간 종료 지점** |
| 4 | `INSPECT` | 검사 노드 | 6칸 판정 결과, 미확인 칸 없음 |
| 5 | `CULL` | 시뮬 실행기 | 대상 칸 제거 확인 |
| 6 | `CONVEYOR_OUT` | 시뮬 실행기 | 출구 감지 |

불량이 없으면 `CULL` 을 생략하고 `CONVEYOR_OUT` 으로 전이함.

### 5-3. 연결 방식 두 가지

**방식 A. 팀 올인원 스테이션 사용**

팀 브랜치의 `scripts/inspection_cull_station.py` 가 검사(YOLO) → 솎아내기 → 재검사 → 배출까지 Isaac Sim 내부에서 자체 진행하며, 종료 시 `inspection_done()` 을 자체 호출함.

| 항목 | 내용 |
|---|---|
| 연결 방법 | 실행 시 `--no-vision-station` 을 제거하면 됨 |
| 준비물 | 검사용 파이썬의 `ultralytics`, 가중치 `best.pt`(장면 폴더에 있음) |
| 특징 | ROS 명령 없이 자동 진행됨. 시연에 유리하나 Task Manager 통제 밖임 |
| 팀 측정치 | 검사 5초, 솎아내기 3포기 92초, 재검사 7초. 시뮬 시간 기준임 |

**방식 B. Task Manager 단계 지휘**

`INSPECT` → `CULL` → `CONVEYOR_OUT` 을 순서대로 발행하는 방식임. 필요 조건은 둘임.

1. 검사 노드가 `/sim_task/command` 의 `INSPECT` 를 수신하고 `defect_slots` 를 반환할 것
2. 검사 종료 시점에 `conveyor.inspection_done()` 이 호출될 것. 팀 스테이션을 쓰지 않는 경우 이 호출을 담당할 주체가 필요함

### 5-4. 다음 구간 담당자용 수치

|---|---|---|

### 5-5. 본 파트의 후속 역할

place 이후 본 파트가 다시 호출되는 경우는 카터를 다른 지점으로 이동시킬 때임. 예를 들어 배출 완료 후 랙으로 복귀시키려면 `NAVIGATION destination=RACK_DOCK` 을 발행하면 됨. 현재 주행 노드가 인식하는 목적지는 `FEEDER_DOCK`, `RACK_DOCK`, `CORRIDOR_EXIT` 세 곳임.

주의 사항 한 건임. 랙 통로 안에서는 제자리 회전을 시키지 않음. 리그가 0.66 m 를 휩쓸어 랙에 접촉하기 때문이며, 경로 계획기가 후진 경로를 직접 생성하도록 설정되어 있음.
