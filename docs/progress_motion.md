# 작업 목표
기존 단일 팔레트 인출 코드(robot_motion.py)를 재사용 가능한 동작 모션 모듈로 바꾸는 것

- PLACE, AMR 주행, 리프트 제어, 검사 공정은 다음 단계로 두되, 이번에 만드는 인터페이스가 그 작업들을 받을 수 있게 설계한다.

## 작업 단계

| 단계       | 작업                                                                | 완료 기준                                            |
| -------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| 1. 현행 분석 | `robot_motion.py`, 장면 prim, 포크 형상·TCP, 기존 IK 설정 확인 | 현재 코드의 동작 조건과 재사용 가능한 부분 정리 |
| 2. 모듈 분리 | 앱·장면 실행 코드와 PICK 모션 코드 분리 | 모션 모듈을 import해도 `SimulationApp`이나 장면이 자동 실행되지 않음 |
| 3. 목표 생성 | 슬롯 기준 자세와 설정된 offset으로 접근·삽입·인양·인출 TCP 목표 생성 | 슬롯 위치를 바꿔도 관절값을 수정하지 않고 목표가 다시 계산됨 |
| 4. 모션 실행 | 현재 베이스 자세를 반영하고, 프레임별로 IK·관절 명령·단계 전환 수행 | 한 슬롯에서 기존 PICK 동작을 재현 |
| 5. 판정·검증 | TCP 경로, 팔레트 상승·인출, 실패·시간초과 확인 | 코드 검사 결과와 Isaac Sim에서 확인할 항목을 구분해 보고 |

---

대상은 `cobot3_ws/isaacpjt/smart_farm/scripts/robot_motion.py`다. 이 파일은 현재 특정 장면, 특정 로봇 베이스 위치, 특정 팔레트에 맞춘 관절 waypoint로 포크 삽입·인양·인출을 수행한다. 이번 작업의 목표는 **기존 PICK 동작을 기준선으로 보존하면서, 슬롯 자세와 설정된 offset을 입력받아 재사용할 수 있는 모션 모듈로 리팩터링하는 것**이다.

## 프로젝트 조건

* 이동체는 Nova Carter다.
* M0609_fork는 Nova Carter 위의 승강 바닥판에 결합될 예정이다. 바닥판이 상승하면 로봇 베이스의 실제 월드 자세도 바뀐다.
* 최종적으로 여러 랙 슬롯에서 PICK/PLACE하고, 팔레트를 검사대로 운반한다.
* 이번 작업의 구현·검증 범위는 **PICK 단위 동작**이다. PLACE, 리프트 구동, AMR 주행, 검사, 솎아내기, 컨베이어 제어는 지금 단계에서는 구현하지 않는다.
* 팔레트 ID 규칙은 다음과 같다.
    * 팔레트: PALLET_001, PALLET_002, … — 개체 번호, 위치 의미 없음
    * 랙 위치: RACK_L1~RACK_L4 — 고정 슬롯
    * 검사대: INSPECT_STATION — 팔레트가 이동할 수 있는 위치
    * 작업 실행: task_id — 순환 작업 1회의 식별자. 팔레트 ID와 별개

## 먼저 확인할 것

1. 현재 `robot_motion.py`의 실행 순서, prim 경로, 관절 인덱스, 도달·팔레트 상승·슬립 판정을 분석해줘.
2. `demo_test.usd`와 관련 에셋에서 로봇 articulation, 포크 끝, 팔레트, 랙 슬롯의 실제 prim 경로와 좌표계를 확인해줘.
3. 저장소에 이미 있는 M0609용 IK·모션 설정이 `M0609_fork`의 현재 형상과 TCP에 적용 가능한지 확인해줘. 적용 여부가 불명확하면 그대로 사용해 성공한 것으로 간주하지 말고, 필요한 설정·보정 항목을 명시해줘.
4. 기존 장면에 슬롯 삽입 기준 prim이 없다면, 실제 prim 구조에 맞는 최소한의 슬롯 자세 입력 방법을 정해줘. 확인되지 않은 prim 경로를 사실처럼 하드코딩하지 말아줘.

## 구현 요구사항

* 앱·장면 실행 코드와 모션 코드를 분리해줘. 모션 모듈을 import할 때 `SimulationApp` 생성, USD 로드, `World.reset()`, 실행 루프 시작, `app.close()`가 일어나면 안 된다.
* `ForkMotion`과 같은 클래스를 제공해줘. 최소한 PICK 시작, 프레임별 `update(dt)`, 실행 상태·실패 원인 조회, reset 기능이 필요하다.
* 슬롯 기준 자세와 설정값으로 `APPROACH → INSERT → LIFT → RETRACT`의 **포크 TCP 목표**를 생성해줘. 접근 거리, 삽입 깊이, 인양 거리, 속도, 허용 오차는 설정으로 분리해줘.
* 삽입·인출 구간은 포크의 높이와 방향을 유지하는 직선 TCP 경로를 목표로 해줘. 관절 시작값과 끝값을 단순 선형 보간하는 방식으로 대체하지 말아줘.
* 매 작업을 시작할 때 승강 바닥판 위 로봇의 **현재 실제 베이스 자세**를 읽어 목표 계산 또는 IK에 반영해줘. 기존의 고정 `ROBOT_BASE_POSITION` 검사가 정상적인 리프트 이동을 막지 않도록 해줘.
* 포크 TCP와 `link_6`을 구분해줘. 현재 포크 치수·장착 변환을 확인하고 TCP 보정값의 출처를 코드나 설정에 명시해줘.
* 각 목표에서 IK 실패, 관절 한계 초과, 도달 시간초과를 실패 결과로 처리해줘. 가능하다면 중간 경로의 포크·랙 간극도 확인하고, 구현하지 못한 충돌 검사를 성공 보장처럼 표현하지 말아줘.
* 관절 도달과 물리적 PICK 성공을 구분해줘. 최소한 팔레트 상승 및 인출 완료를 확인하고, 기존 코드의 `LIFT` 중 팔레트가 옆으로 밀리는 경우도 검토해줘.
* Isaac Sim의 기존 실행 파일에서 모션 모듈을 호출해 단일 슬롯 PICK을 시험할 수 있도록 해줘. 실행 파일이 시뮬레이션 앱과 프레임 루프를 한 번만 소유해야 한다.

파일 구성은 아래를 출발점으로 검토하되, 저장소의 실제 구조에 더 잘 맞는 형태가 있으면 이유를 설명하고 조정해줘.

```text
cobot3_ws/isaacpjt/smart_farm/
├── motion/
│   ├── __init__.py
│   ├── fork_motion.py
│   ├── target_builder.py
│   └── motion_config.py
└── scripts/
    └── robot_motion.py
```
