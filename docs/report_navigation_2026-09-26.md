### 2-2. 네 가지가 각각 무엇인지 (쉬운 설명)

**① Place 전 안전 확인** — 자동차가 완전히 멈추기 전에 짐을 내리면 위험합니다. 예전에는 "도착했다"는 신호만 오면 로봇 팔이 바로 움직였는데, 카터가 아직 미세하게 미끄러지는 중일 수 있었습니다. 이제는 **차체가 0.5초 이상 실제로 정지한 것을 확인한 뒤에만** 팔이 움직입니다. 안 멈추면 팔을 움직이지 않고 "아직 안 멈췄음"이라고 알려 줍니다.

**② 도킹 위치 기록** — 카터가 실제로 **어디에 멈췄는지 좌표를 한 줄 남깁니다.** 판정은 하지 않고 기록만 합니다. 이 값이 있어야 "팔이 닿는 거리가 얼마인가"를 숫자로 정할 수 있습니다. 실제로 이번 통과에서 이 줄 덕분에 `팔 베이스에서 놓을 자리까지 0.809 m` 라는 값을 얻었습니다.

```
[도킹] 카터 본체 world (-2.161, -2.738), place 대상까지 x -0.026 m, y -1.169 m, 직선 1.170 m
```

**③ 앱이 죽던 문제 막기** — 팀 코드에는 "운반 중 팔레트가 30 mm 넘게 밀리면 오류를 낸다"는 안전 검사가 있습니다. 그런데 그 오류가 프로그램 바깥까지 튀어나와 **Isaac Sim 전체가 종료**되곤 했습니다(2026-09-24 실측에서 실제로 발생). 이제는 그 오류를 받아서 **기록 한 줄만 남기고 계속 진행**합니다. 안전 검사를 없앤 것이 아닙니다 — 다음 Place 명령 때 같은 검사가 다시 돌고, 그때는 "동작 실패"라는 **결과 메시지로 정상 보고**됩니다. 즉 *"실패를 숨긴 것"이 아니라 "앱을 죽이는 대신 결과로 알리게"* 바꾼 것입니다.

**④ 녹화용 카메라 선택** — 장면 파일에 저장된 기본 시점이 비전룸을 비추고 있어서, 화면을 녹화하면 **정작 카터가 안 보였습니다.** 지금까지는 사람이 마우스로 카메라를 바꿔야 했습니다. 이제 실행할 때 환경변수 한 줄을 주면 원하는 카메라로 자동 전환됩니다. **환경변수를 주지 않으면 아무 일도 하지 않으므로 팀의 기존 실행에는 영향이 없습니다.**

```bash
export SMARTFARM_VIEW_CAMERA=/World/ProcessCameras/Cam2_Nav2Place
```

### 2-3. 되돌리기

네 가지 모두 **추가만 했고 팀 줄은 건드리지 않았습니다.** `[navigation 날짜]` 주석이 붙은 블록만 지우면 팀 원본으로 돌아갑니다. 파일 되돌리기(`git revert`)는 다른 변경과 섞이므로 권하지 않습니다.

## 4. 자주 바꾸게 되는 값들

숫자를 바꾼 뒤에는 **반드시 `colcon build` 를 다시 해야 반영됩니다.** 실행 묶음은 빌드된 복사본을 읽기 때문입니다.

### 4-1. 정밀 도킹 — `smart_farm_navigation/feeder_dock.py` 의 `DockParams`

| 변수 | 현재값 | 뜻 | 바꿀 때 |
|---|---|---|---|
| `standoff_m` | **0.92** | 라이다가 본 면에서 얼마나 떨어져 설 것인가 (m) | **팀의 place 수정과 한 쌍입니다. 임의로 바꾸지 마십시오.** 팔이 안 닿을 때만, place 코드와 함께 검토 |

## 5. Place 이후 — 다음 구간과 어떻게 잇는가

### 5-1. 우리 구간이 끝나는 지점

우리 구간은 **`PLACE_INSPECT` 가 성공(`SUCCEEDED`)으로 끝나는 순간**까지입니다. 그 시점의 상태는 다음과 같습니다.

| 항목 | 상태 |
|---|---|
| 팔레트 | 턴테이블 줄기 벨트 위에 놓임 |
| 카터 | 도킹 자세 그대로 정지. 팔은 인출 완료 |
| 컨베이어 | 놓는 동안 멈춰 있다가 **자동으로 재가동**되어 팔레트를 비전룸 쪽으로 보냅니다 |
| 결과 메시지 | `/sim_task/result` 에 `PLACE_INSPECT / SUCCEEDED` |

2026-09-26 통과 때 실제 로그입니다.

```
[컨베이어] 줄기 벨트 정지 (로봇 놓기 중)
[컨베이어] Pallet_01 벨트 감지 — 반송 시작 (-2.186, -3.550)
[컨베이어] 줄기 벨트 재가동
[컨베이어] Pallet_01 카메라 앞 정지 (-0.496, -6.728)
```

즉 **팔레트는 이미 비전룸 카메라 앞까지 스스로 옮겨져 멈춰 있습니다.** 다음 구간은 여기서 시작하면 됩니다.

### 5-2. 인계 지점은 두 곳뿐입니다

**인계 지점 ①: 컨베이어의 "검사 끝났다" 신호**

컨베이어는 팔레트를 카메라 앞에 세운 뒤 **다음 둘 중 하나를 기다립니다.**

| 설정 | 동작 | 언제 쓰나 |
|---|---|---|
| `auto_resume=None` | `inspection_done()` 이 불릴 때까지 **무한정 기다립니다** | 검사 담당이 붙었을 때 (정식) |
| `auto_resume=10.0` | 10초 뒤 알아서 내보냅니다 | 검사 없이 앞 구간만 돌려 볼 때 (지금 우리 설정) |

현재 팀 코드는 `--no-vision-station` 여부에 따라 이 둘을 자동으로 고릅니다(`standalone_app.py`). **다음 구간을 붙인다는 것은 결국 "검사가 끝나면 `conveyor.inspection_done()` 을 불러 주는 주체를 정하는 일"입니다.**

**인계 지점 ②: Task Manager 의 명령 순서**

인터페이스 설계서(`docs/02-interfaces.md`)에 이미 순서가 정의되어 있습니다. 우리 구간 다음은 세 단계입니다.

| 순서 | operation | 받는 쪽 | 성공 조건 |
|---|---|---|---|
| 1 | `PICK_HARVEST` | 시뮬 실행기 | `safe_to_navigate=true` |
| 2 | `NAVIGATION` | **주행 노드(우리)** | `reached_station=FEEDER_DOCK` |
| 3 | `PLACE_INSPECT` | 시뮬 실행기 | 놓기 검증 통과 ← **여기까지가 우리 구간** |
| 4 | `INSPECT` | 검사 노드 | 6칸 판정 결과, 미확인 칸 없음 |
| 5 | `CULL` | 시뮬 실행기 | 대상 칸 제거 확인 |
| 6 | `CONVEYOR_OUT` | 시뮬 실행기 | 출구 감지 |

> 불량이 없으면 `CULL` 을 건너뛰고 바로 `CONVEYOR_OUT` 으로 갑니다.

### 5-3. 붙이는 방법 두 가지

**방법 A — 팀이 이미 만든 올인원 스테이션을 쓰는 방법 (빠름)**

팀 브랜치에 `scripts/inspection_cull_station.py` 가 있고, 검사(YOLO) → 솎아내기 → 재검사 → 배출까지 **Isaac 안에서 스스로** 진행합니다. 끝나면 자기가 `inspection_done()` 을 불러 줍니다.

- 붙이는 법: 시뮬레이터를 띄울 때 `--no-vision-station` 을 **빼면** 끝입니다.
- 준비물: 검사용 파이썬에 `ultralytics` 설치, 가중치 `best.pt`(장면 폴더에 있음)
- 특징: ROS 명령 없이 자동으로 이어집니다. 시연에는 편하지만 **Task Manager 가 통제하지는 않습니다**
- 팀 측정치: 검사 5초, 솎아내기 3포기 92초, 재검사 7초 (시뮬 시간)

**방법 B — Task Manager 가 단계별로 지휘하는 방법 (설계서대로)**

`INSPECT` → `CULL` → `CONVEYOR_OUT` 명령을 순서대로 보내는 방식입니다. 이때 필요한 것은 두 가지뿐입니다.

1. **검사 노드가 `/sim_task/command` 의 `INSPECT` 를 받아 결과(`defect_slots`)를 돌려줄 것**
2. **검사가 끝나는 시점에 `conveyor.inspection_done()` 이 불릴 것** — 팀 스테이션을 쓰지 않는다면 이 한 줄을 누군가 불러 주어야 컨베이어가 다시 움직입니다

### 5-5. Navigation 쪽에서 추가로 해야 할 일

**Place 이후 우리 구간이 다시 호출될 수 있는 경우는 "카터를 다른 곳으로 보낼 때"뿐입니다.** 예를 들어 배출이 끝난 뒤 랙으로 복귀시키려면 `NAVIGATION destination=RACK_DOCK` 명령을 보내면 됩니다. 현재 주행 노드가 아는 목적지는 `FEEDER_DOCK`, `RACK_DOCK`, `CORRIDOR_EXIT` 세 곳입니다.

주의할 점 하나: **카터가 도킹 자세로 서 있는 동안에는 랙 통로 안에서 제자리 회전을 시키지 않습니다.** 리그가 0.66 m 를 휩쓸어 랙에 닿기 때문이며, 경로 계획기가 후진 경로를 직접 만들도록 설정되어 있습니다.
