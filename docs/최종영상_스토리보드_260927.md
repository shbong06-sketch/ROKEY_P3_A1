- 근거 문서: `docs/00-Business_Requirement_Document/비즈니스 정의*.md`(문제 정의), `docs/고도화_개발_일정_및_발표_준비.md`(9/27 회의 결정), `docs/03-task-manager.md`·`docs/POST_PLACE_TO_INSPECT_CHECK.md`(공정 순서)

- 소스 제출 기한: **2026-09-28(월)** · Google Drive

> **먼저 읽을 것 — 녹화 전에 반드시 지켜야 하는 3가지**
> 1. **30 fps 이상으로 녹화할 것.** 현재 `record_rig.sh` 기본값은 10 fps 인데, 이 소스를 본문에서 3~4배속하면 **초당 2.5~3장**이 되어 못 씀. `FPS=30` 으로 바꿔 녹화함
> 2. **같은 사이클을 카메라만 바꿔 3~4회 반복 녹화할 것.** 한 번의 실행에서 여러 시점을 동시에 얻을 수 없음. 통합 시나리오는 재실행이 되도록 만들었으므로(9/27 회의 결정 4), **초기 조건을 바꾸지 말고** 같은 동작을 반복해 찍음
> 3. **실패 테이크도 지우지 말 것.** 도입부·부록에서 쓸 수 있음. 특히 도킹 재시도, HumanStop 정지는 성공 영상보다 가치가 큼

## 0. 영상 규격과 파일 제출 규칙

| 항목 | 값 | 비고 |
|---|---|---|
| 해상도 | **1920×1080** | 현재 `record_rig.sh` 는 Isaac 1440×900 · RViz 1680×1050 임. 편집 시 확대하면 흐려지므로 1080p 로 올려 녹화 |
| 프레임 | **30 fps 이상** | 배속 편집의 전제 조건 |
| 코덱·컨테이너 | H.264 / `.mp4` | |
| 오디오 | 없음(무음) 상태로 제출 | 음악·내레이션은 편집에서 일괄 |
| 화면 구성 | **Isaac 뷰포트 단독 녹화**를 기본으로 함 | 3분할(`record_rig.sh`)은 부록·메이킹용. 본문에는 패널·툴바가 보이지 않게 |
| 파일명 | `S{장}-{컷}_{모듈}_{시점}_{테이크}.mp4` | 예: `S4-02_dock_카터뷰_t2.mp4` |
| 함께 올릴 것 | 같은 실행의 **로그(`results/` tee 출력)와 bag** | 오버레이에 넣을 수치의 출처가 됨 |

**시점(샷) 이름은 아래 9가지로 통일함.** 파일명과 표에 그대로 씀.

| 이름 | 카메라 위치 | 쓰는 곳 |
|---|---|---|
| 마스터샷 | 구역 전체가 한 화면에 드는 고정 | 장 시작·끝 |
| 롱샷 | 로봇이 화면의 1/4 정도 | 이동 구간 |
| 풀샷 | 로봇 전체가 꽉 참 | 동작 소개 |
| 조감 | 바로 위에서 수직 | 경로·배치 설명 |
| 부감 | 45° 위 | 기본 시점 |
| 로우샷 | 바닥 높이 | 리그가 다가오는 압박감 |
| 팔레트뷰 | 팔레트에 붙임 | 운반·안착 |
| 그리퍼뷰 | 손목/그리퍼에 붙임 | 집기·솎아내기 |
| 카터뷰 | 차체 뒤(팔 쪽)에 붙임 | 후진 도킹 |

**시점 전환 방법** — 장면에 카메라 prim 을 미리 만들어 두고, 실행할 때 환경변수 한 줄로 고릅니다. 이미 지원되는 기능임.

```bash
export SMARTFARM_VIEW_CAMERA=/World/ProcessCameras/Cam2_Nav2Place
```

- 이미 있는 카메라: `Cam2_Nav2Place`
- **추가로 만들어야 하는 카메라 8개**(담당: 장면 담당 + 각 모듈 담당이 자기 장에 필요한 것):
  `Cam_Master_Overview`(조감) / `Cam_Rack_Front`(부감) / `Cam_Corridor_Low`(로우샷) / `Cam_Dock_Side`(풀샷) /
  `Cam_Carter_Rear`(카터뷰, 차체 −x 에 부착) / `Cam_Pallet`(팔레트뷰, 팔레트에 부착) /
  `Cam_VisionRoom_High`(부감) / `Cam_Wrist`(그리퍼뷰, 비전 M0609 손목)

## 5. EX. 개발 중인 고도화 (1:10) — **엔딩 뒤에 배치**

### 5-1. 어디에 넣을지에 대한 판단

**결론: 본문 안이 아니라, 엔딩이 끝난 뒤 별도 챕터로 붙임.** 이유 4가지임.

1. **본문은 「정상 시나리오 한 사이클을 끊김 없이 완주한다」는 하나의 약속을 지키는 구조임.** 중간에 미완성 모듈이 끼면 그 약속이 흐려지고, 보는 사람은 "이건 되는 건가 안 되는 건가" 를 계속 의심하게 됨
2. **화면 문법이 다름.** 고도화는 모듈 단위 시험이 기본이라(9/27 회의) 통합 장면이 아니라 웹 화면·그래프·터미널이 주가 됨. 본문의 3D 공정 화면 사이에 끼면 톤이 튐
3. **엔딩이 「앞으로」를 말하므로 그 뒤가 문맥상 오히려 맞음.** 미래 전경 → **「그래서 지금 이것을 만들고 있습니다」** 로 자연스럽게 이어짐
4. **리스크 격리.** 승인 여부가 마감 직전에 갈리는 항목이므로(팀장 승인 시에만 통합 적용), 챕터 단위로 통째로 넣고 빼야 본편을 다시 건드리지 않음

**예외 하나** — ML 이상 탐지가 발표 가능한 수준에 도달해 **5번째 챌린지로 확정되면**, 본문 5(검사) 뒤에 **15초 인서트**로 올려도 됨. 이상 탐지는 공정 데이터를 쓰므로 본문과 화면 문법이 같기 때문임. 그 경우에도 EX. 챕터에는 남겨 두고 본문 인서트는 짧게만 씀.

## 8. 편집 규칙

- **컷 전환**: 같은 장 안에서는 하드컷. 장이 바뀔 때만 0.3초 디졸브. 화려한 전환 효과는 쓰지 않음

- **음악**: 도입부는 저음 위주로 눌러 두고, S2-05 제목에서 올림. EX. 챕터는 음악을 빼고 무음에 가깝게 — 본편과 구분됨
- **저작권**: 폰트·음악·영상 소재는 배포 가능한 것만 씀. 외부 저장소 링크를 영상이나 PPT 에 넣지 않음(튜터 지시)

| AI 생성 영상의 품질이 안 나옴 | 엔딩을 조감 마스터샷 + 타이틀로 마무리. 도입부는 문자 타이포만으로도 성립함 |
| 10 fps 소스만 확보됨 | 그 구간은 배속하지 않고 실시간으로 쓰거나, 정지 화면 + 오버레이로 대체 |
| 길이 초과 | 본문 1(TRANSFER)과 본문 6(CONVEYOR_OUT)을 각각 절반으로 줄임. 본문 2·5 는 줄이지 않음 |

## 10. 확정이 필요한 것 (팀 회신 요청)

1. **비전(검사·솎아내기) 영상 담당자** — 표의 「담당 확정 필요」 칸
2. **내레이션 유무** — 자막만으로 갈지, 발표자 음성을 넣을지. 음성을 넣으면 길이가 10~15% 늘어남
3. **본문 7 의 지표 3개 확정값** — 공정 완료율, 사이클 시간. 측정 전이면 카드를 2장으로 줄임
4. **ML 이상 탐지의 5번째 챌린지 확정 여부** — 확정 시 본문 5 뒤 15초 인서트로 승격
5. **EX. 챕터 포함 여부 최종 결정** — 현재 초안은 포함 기준으로 8분 45초임
6. **클래스별 분류 투하(S8-05) 반영 여부** — 현재 코드는 통을 번갈아 씀. 9/28 전 반영 가능한지
