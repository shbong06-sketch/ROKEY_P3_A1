# 트러블슈팅 — 화면 없는 VM 에서 Isaac Sim 운용·녹화 환경 구축

- 날짜: 2026-09-26 (UTC 00:45 ~ 02:56)
- 기기: 고피3 (GCP VM `gc-isaacsim-lwh`, NVIDIA L4 23 GB, Xeon 2.20 GHz 6C/12T, RAM 48 GB, Ubuntu 24.04.5, Isaac Sim 5.1.0, ROS 2 Jazzy)
- 주제: **물리 모니터가 없는 클라우드 VM 에서 Isaac Sim 과 RViz2 를 실제로 그려서 영상으로 남기는 환경을 만든 과정**
- 근거: 이 폴더의 `run_*` 4개(`start_time.txt`, `ffmpeg_*.log`, `xvfb_*.log`, `*.mp4`), `results/log/isaacpilot2_xvfb_20260926_0004.txt`, `scripts/record_rig.sh` 의 커밋 이력, `guidance/guidance2_26차.md`
- **복원 이력**: 이 문서는 `38a946f`(2026-09-28)에서 이 경로에 만들어졌으나, `d2e2ebb`(2026-09-29 12:28, "fix:nav 쪽 result/가 일로 옴")에서 nav 쪽 `results/` 를 옮기는 과정에 **함께 지워졌음.** 2026-09-29 에 `d2e2ebb^` 에서 같은 내용으로 되살렸음 (CLAUDE.md §3 — 삭제는 우리 기록을 이기지 못함).
- 작성 참고: 이 환경 구축은 에이전트가 VM 에서 수행한 작업이라 자동화 흔적이 섞여 있음. 아래는 **환경 구축이라는 주제로 재정리한 것**이며, 로봇 동작에 대한 실측 판정이 아님.

---

## 0. 왜 이 작업이 필요했는가

VM 에는 `DISPLAY` 가 없음. 그렇다고 Isaac 을 `--headless` 로 띄우면 **ROS 토픽이 하나도 나오지 않음**(`/clock` 0 Hz, 라이다 없음, GPU 0 %). OmniGraph tick 이 돌지 않기 때문임. 따라서 **가상 디스플레이(Xvfb)에 실제로 그려서 띄워야** 하고, 그 화면을 그대로 캡처하면 실측 영상까지 함께 얻을 수 있음. 이 목적으로 만든 것이 `scripts/record_rig.sh` 임.

---

## 1. `run_20260926_0045` — 첫 시험 녹화, Isaac 화면이 비어 있었음

- 시작 00:45:39Z, 세 영상 모두 155.2 초. 화면 번호가 아직 `:87`/`:88`/`:89` 였음(고정 규칙 이전).
- **문제**: 같은 155 초인데 `terminal.mp4` 는 5.5 MB, `isaac.mp4` 는 **99 KB** 로 사실상 정지화면이었음. `xvfb_88.log` 만 xkb 블록이 1개(나머지 두 화면은 2개)여서 그 화면에 붙은 클라이언트가 하나뿐이었음 — 판이 의도한 화면에 붙지 않았다는 정황임.
- **해결**: 화면 번호를 `:99` Isaac / `:98` RViz2 / `:97` 터미널로 **고정**하고, 판마다 `export DISPLAY=:9x` 를 명시해 붙이는 절차를 `guidance2_26차.md` 2-1절로 못박음. 창 관리자가 없어 한 화면에 두 창을 띄우면 겹치고 잘리므로 화면을 셋으로 나눈 것도 이때 정한 구조임.

## 2. `run_20260926_0056` — 시작 자체가 실패, 폴더만 남음

- 폴더는 만들어졌으나 **파일이 하나도 없음.** 직전 00:50 커밋 `0fed73f` 가 "시작 도중 실패하면 흔적을 지우고 나간다"(`abort()`)를 넣었기 때문에, 실패가 그대로 빈 폴더로 드러난 것임. 이 처리가 없으면 다음 `start` 가 "이미 녹화 중" 으로 막힘.
- **문제**: 앞서 띄워 둔 Isaac 이 같은 화면 번호를 이미 쓰고 있었음(`:$N 는 이미 쓰이고 있다`).
- **해결과 그 과정에서 겪은 사고**: 그 Isaac 을 끄려고 `pkill -f standalone_app.py` 를 썼다가 **그 문자열이 명령줄에 들어 있던 다른 셸까지 함께 죽었음.** 00:58 커밋 `e92e673` 에서 `pkill -f` 사용을 **금지**로 바꾸고 `ps -ef | grep isaacsim` 으로 PID 를 찾아 `kill` 하도록 절차와 스크립트 안내문을 고쳤음.

## 3. `run_20260926_0111` — 첫 성공 녹화, 터미널 한글이 전부 빈칸

- 시작 01:11:24Z, 세 영상 모두 633.2 초로 길이가 일치하고 내용도 정상(isaac 2.4 MB / rviz 2.6 MB / terminal 13.4 MB). 화면 번호 고정(`:97`/`:98`/`:99`)이 적용된 첫 판임.
- **문제**: `terminal.mp4` 에서 **한글이 모두 빈칸**으로 찍힘. 이 VM 에 한글 글꼴이 하나도 설치되어 있지 않은 상태에서 xterm 을 `-fa Monospace` 로 띄웠기 때문임.
- **해결**: 01:32 커밋 `1540513` 에서 `sudo apt-get install -y fonts-nanum-coding` 으로 한글 고정폭 글꼴을 넣고, xterm 의 `-fa`/`-fw` 에 그 글꼴을 직접 지정했음.

## 4. `run_20260926_0132` — 한글은 나왔으나 자간이 벌어짐 (판정 근거가 된 판)

- 시작 01:32:43Z, 세 영상 594.5 초. `guidance2_26차.md` 에 **"세 화면 594 초, 실제 경과 609 초의 98 %, 프레임 손실은 무시할 수준"** 으로 기록된 판이 이것임. 즉 **VM 에서 Isaac·RViz2·터미널 3분할 녹화가 성립한다는 결론의 근거**임.
- **문제**: 한글은 나오지만 **영문·숫자까지 한글 글꼴로 그려 자간이 벌어져 읽기 나빠짐.** Noto CJK 를 `-fa` 에 주면 더 심해졌음.
- **해결**: 02:54 커밋 `3b31b1a` 에서 보통 폭 글자는 `-fa "DejaVu Sans Mono"`, 두 칸 폭(한글)은 `-fw "Noto Sans Mono CJK KR"` 로 **분리**했음. 결과는 같은 폴더의 `font_check_after_fix.png`(02:56)로 확인했음.

## 5. 정리 — 이 환경에서 다시 쓸 규칙

| # | 규칙 | 겪은 증상 |
|---|---|---|
| 1 | 화면 없는 VM 에서도 **Isaac 을 `--headless` 로 띄우지 않음.** `xvfb-run` 또는 고정 `Xvfb` 로 실제로 그려서 띄움 | `/clock` 0 Hz, 라이다 토픽 없음, GPU 0 % |
| 2 | **화면을 셋으로 나눔** (`:99` Isaac / `:98` RViz2 / `:97` 터미널). 가상 화면에는 창 관리자가 없어 한 화면에 두 창이면 겹치고 잘림 | RViz2 3D 뷰가 화면 오른쪽 끝을 넘어가 잘림 |
| 3 | 화면 번호는 **고정**하고 판마다 `DISPLAY` 를 명시함. `xvfb-run -a` 로 띄우면 번호와 `XAUTHORITY`(`-auth` 경로)를 매번 찾아야 함 | Isaac 화면이 빈 화면으로 녹화됨(1절) |
| 4 | 창 정렬은 `xdotool` 로 0,0 에 맞춤 (`record_rig.sh fit`) | 창 관리자 없음 |
| 5 | **`pkill -f <패턴>` 을 쓰지 않음.** `-f` 는 명령줄 전체를 보므로 그 문자열이 든 다른 셸까지 죽임. PID 를 찾아 `kill` 함 | 끄려던 것 말고 다른 셸이 같이 죽음(2절) |
| 6 | 시작 실패 시 **흔적을 지우고 원인을 출력**함 | 남은 흔적 때문에 다음 `start` 가 "이미 녹화 중" 으로 막힘 |
| 7 | 한글 글꼴은 **따로 설치**하고 xterm 의 `-fa`(영문)와 `-fw`(한글)를 **분리**해서 지정함 | 한글 빈칸(3절) → 자간 벌어짐(4절) |
| 8 | Isaac 의 **Stop 버튼을 누르지 않음.** 종료는 그 판에서 `Ctrl+C` | 팀 앱이 종료 처리에서 죽음 |
| 9 | 녹화 전에 **Isaac 뷰포트 카메라를 보고 싶은 공정으로 바꿈**. 기본 Perspective 는 비전룸을 봄 | 원하는 공정이 화면에 없음 |
| 10 | `ffmpeg` x11grab 의 `not enough frames to estimate rate; consider increasing probesize` 는 **무해함.** 시작 순간 프레임이 적어 나오는 알림이며 4개 판 전부에 동일하게 나왔고 녹화는 정상이었음 | 모든 `ffmpeg_*.log` |
| 11 | `xvfb_*.log` 의 `Could not resolve keysym XF86…` xkb 경고도 **무해함**(`Errors from xkbcomp are not fatal to the X server`) | 모든 `xvfb_*.log` |
