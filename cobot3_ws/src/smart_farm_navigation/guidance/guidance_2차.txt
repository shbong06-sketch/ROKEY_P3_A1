[2차] escape_controller YAML 파일 열기 오류 복구 가이드

확인된 오류
- rclpy가 --params-file 뒤의 escape_controller.yaml을 열지 못해 초기화 전에 종료되었다.
- colcon build는 성공했으므로 Python 패키지와 escape_controller 실행 entry point는 정상이다.
- 원인은 고피 작업 경로에 config/escape_controller.yaml이 아직 동기화되지 않았거나, 소스 경로를 직접 지정해 발생한 것이다.

1. 고피에서 feature/navigation 최신 변경 사항을 받은 뒤 파일 존재를 확인한다.

cd /home/rokey/ROKEY_P3_A1
git pull --ff-only origin feature/navigation
test -r cobot3_ws/src/smart_farm_navigation/config/escape_controller.yaml && echo "config 확인됨"

2. 패키지를 다시 빌드하고, 설치된 설정 파일 경로를 확인한다.

cd /home/rokey/cobot3_ws
ros_set
colcon build --packages-select smart_farm_navigation --symlink-install
source install/setup.bash
ros2 pkg prefix smart_farm_navigation
test -r "$(ros2 pkg prefix smart_farm_navigation)/share/smart_farm_navigation/config/escape_controller.yaml" && echo "installed config 확인됨"

3. Isaac Sim에서 smart_farm_nav2_01.usd를 열고 Play를 누른 상태로, 대기 실행한다.

ros2 run smart_farm_navigation escape_controller --ros-args --params-file "$(ros2 pkg prefix smart_farm_navigation)/share/smart_farm_navigation/config/escape_controller.yaml"

기대 결과
- "Prepared for /cmd_vel; waiting for /chassis/odom" 로그가 출력된다.
- auto_start=false 및 이동값 0.0이므로 로봇은 움직이지 않는다.

중단 조건
- 1단계 또는 2단계의 test 명령이 실패하면 실행하지 않는다.
- 실패한 명령의 출력 전체를 errored/에 새 txt 파일로 저장한다.
